# 私募净值更新与外发操作手册

本手册用于每周维护私募产品净值库，并将本次新增净值汇总后通过 163 邮箱外发。

## 一、文件与职责

所有相关文件均位于 `Private_NAV/`，与 `NAV/zhaoyang/` 无关。

| 文件/目录 | 用途 |
| --- | --- |
| `私募名单.xlsx` | 产品主名单。产品名称和备案编码以此为准。 |
| `私募净值.xlsx` | 净值库；每个产品一个工作表，列为“日期、单位净值、累计净值”。 |
| `inbox/更新.xlsx` | 批量历史/常规更新源，优先处理。 |
| `inbox/` 下的图片 | 周度截图输入；可含产品名，也可能需要按历史净值匹配。 |
| `output/新增净值_*.xlsx` | 每次处理生成的新增净值汇总和待复核清单，可作为邮件附件。 |
| `backups/私募净值_*.xlsx` | 每次实际写入前自动创建的备份。 |
| `import_update_workbook.py` | 将 `更新.xlsx` 导入净值库。 |
| `update_nav_library.py` | 将截图识别结果（CSV 批次）写入净值库。 |
| `smtp_163.py` | 通过 163 SMTP 发送附件。 |

不要直接在 `私募净值.xlsx` 中手工覆盖整张表。所有正式更新先经脚本校验并保留备份。

## 二、固定规则

1. `私募名单.xlsx` 是准入名单。产品尚未加入名单时，不导入净值。
2. 截图中标注的“估值”按净值处理；在批次备注中注明“估值按净值处理”。
3. 同一产品、同一日期、数值完全一致的记录会跳过，不重复写入。
4. 同一产品、同一日期但净值不同的记录标为“冲突/待复核”，不会自动覆盖历史值。
5. 截图未显示产品名时，只能在历史净值特征能**唯一且有把握**地对应产品时导入；不确定即进入待复核，绝不猜测写库。
6. `更新.xlsx` 中的空值及未来日期占位行会被跳过。
7. 实际写库前一定先做一次预检；外发前一定先打开本次 `新增净值_*.xlsx` 核对。
8. 截图批次 CSV 为临时过程文件。确认净值库写入和汇总生成后，删除本次生成的 `Private_NAV/batch_*.csv`；不可删除用户直接提供的输入文件。
9. 截图数值与该产品历史量级明显不一致时，必须检查平台展示口径（例如百倍/千倍展示）。先用相邻日期历史值验证换算比例，再写入库；不得把原始展示值直接写成异常跳变。
10. 应用包名、渠道名称、管理人相似度和收益相关性只能作为辅助证据，不能单独确定无名截图的产品。产品身份与数值口径必须分别核验。

### 口令约定

- “更新净值”默认指处理 `inbox/` 中的净值截图并更新 `私募净值.xlsx`。
- “发送净值”默认指发送收到口令前 **1 小时内实际写入净值库** 的全部新增净值；窗口以口令到达时间为截止点。
- “发送邮箱”默认指把最近一次实际更新的新增净值汇总发送至 `harryji088@163.com`。

## 三、每周标准流程

```text
更新.xlsx（如有） ─┐
                    ├─→ 预检 ─→ 实际写入净值库 ─→ 新增净值汇总 ─→ 人工核对 ─→ 邮件外发
净值截图            ─┘                         └─→ 待复核：不写入，待确认后再处理
```

建议先处理 `inbox/更新.xlsx`，再处理截图。这样截图中未显示名称的净值有更完整的历史库可供比对。

## 四、维护产品名单

新增产品时，先在 `私募名单.xlsx` 中增加一行，至少填写：

| 产品名称 | 备案编码 |
| --- | --- |
| 平方和鼎盛中证1000指数增强127号A期 | SAHB69 |

若 `更新.xlsx` 的列标题与名单正式名称不同，还需在 `import_update_workbook.py` 的 `COLUMN_MAP` 中维护别名映射，例如：

```python
"平方和1000": "平方和鼎盛中证1000指数增强127号A期",
```

新增映射后，先运行预检，确认汇总中的产品名称正确再执行 `--apply`。不要仅凭相似名称新增映射。

## 五、导入 `更新.xlsx`

在项目根目录执行。默认源文件为 `inbox/更新.xlsx`。

### 1. 预检（不会修改净值库）

```bash
python3 Private_NAV/import_update_workbook.py --source inbox/更新.xlsx
```

预检会读取已配置的产品列和日期/净值，检查产品是否在主名单，识别新增、重复和冲突记录，并在 `Private_NAV/output/` 生成 `新增净值_时间戳.xlsx` 供查看。

### 2. 查看报告

报告含两个工作表：

- `新增净值`：准备写入或已写入的记录；
- `待复核`：已存在相同记录、同日冲突、未映射产品或格式异常等记录。

重点核对产品名称、日期、单位净值、累计净值，以及是否出现不应导入的产品。

### 3. 实际写入

确认无误后执行：

```bash
python3 Private_NAV/import_update_workbook.py --source inbox/更新.xlsx --apply
```

脚本会先在 `Private_NAV/backups/` 生成带时间戳的净值库备份，然后更新 `私募净值.xlsx`，并生成本次可外发的新增净值汇总文件。

## 六、处理净值截图

### 1. 识别与匹配

逐张读取 `inbox/` 中的截图，提取截图文件名、页面显示的产品名（如有）、净值日期、单位净值、累计净值，以及是否为“估值”。

匹配优先级：

1. 截图明确显示的产品名，按名单正式名或已维护的别名匹配；
2. 截图未显示产品名时，先比较截图日期与库内相邻日期，再测试合理的展示比例（原值、`/100`、`/1000` 等），同时核对绝对量级、涨跌方向和变化幅度；
3. 只有产品候选唯一、换算比例稳定且换算后的净值能与该产品历史连续衔接时才接受匹配；
4. 应用来源、产品管理人、名称相似和收益相关性只用于佐证，不能替代净值量级与连续性核验；
5. 仍不确定时保留为待复核，不写入净值库。用户确认产品后，仍需独立核对数值展示口径。

### 2. 建立批次 CSV

将确认可导入和待复核记录写入一个 CSV，例如 `Private_NAV/batch_20260826.csv`。表头必须完全如下：

```csv
source_file,observed_name,matched_name,date,unit_nav,cumulative_nav,status,notes
```

示例：

```csv
source_file,observed_name,matched_name,date,unit_nav,cumulative_nav,status,notes
20260821_半夏.jpg,半夏宏观对冲,半夏宏观对冲,2026-08-21,0.9222,0.9222,accepted,截图净值
20260821_产品A.jpg,产品A,,,,,review,产品名或历史匹配尚未确认
20260821_估值.jpg,某产品,某产品,2026-08-21,1.0385,1.0385,accepted,估值按净值处理
```

注意：待复核行的 `status` 必须为 `review`；只有 `status=accepted` 且产品已在名单中的记录会尝试写库。

### 3. 预检与写入

```bash
python3 Private_NAV/update_nav_library.py --batch Private_NAV/batch_20260826.csv
python3 Private_NAV/update_nav_library.py --batch Private_NAV/batch_20260826.csv --apply
```

第一条命令只预检并生成报告；第二条命令才会备份和更新 `私募净值.xlsx`。

## 七、更新后核查

每次 `--apply` 后至少检查：

1. 终端汇总中的“新增、重复、冲突、待复核”数量是否符合预期；
2. `私募净值.xlsx` 中涉及产品的工作表，日期是否递增、是否出现重复日期或空行；
3. 本次 `output/新增净值_*.xlsx` 的 `新增净值` 工作表；
4. `待复核` 工作表中的冲突、不确定匹配和未纳入名单产品。

如发现问题，优先用本次操作前的 `backups/私募净值_*.xlsx` 对照定位；不要直接删除或批量覆盖数据。

## 八、生成并外发邮件

详细 SMTP 配置说明见 [`EMAIL_USAGE.md`](EMAIL_USAGE.md)。

### 发送窗口规则（口令“发送净值”）

1. 记收到“发送净值”口令的时间为 `T`，统计窗口为 `[T-60 分钟, T]`。
2. 只汇总窗口内成功执行 `--apply` 后实际写入 `私募净值.xlsx` 的新增记录；预检生成的报告不算实际新增。
3. 如果窗口内有多次实际写入，将其合并为一份附件，并按“基金名称 + 净值日期”去重；数值以发送前的当前净值库为准。
4. 已撤销、误匹配、误缩放或随后更正的记录不得发送；发生更正时只保留当前净值库中的有效版本。
5. 窗口内没有实际新增时，不发送空附件，直接告知用户无可发送数据。
6. 附件发送至 `harryji088@163.com`。先打开合并后的“新增净值”工作表核对，再执行 dry-run，确认收件人和附件无误后正式发送。

### 1. 配置 163 邮箱

在项目根目录的 `.env`（或 `Private_NAV/.env`）中配置：

```dotenv
MAIL_HOST=smtp.163.com
MAIL_PORT=465
MAIL_USER=your_account@163.com
MAIL_PASSWORD=163客户端授权密码
MAIL_FROM=your_account@163.com
```

`MAIL_PASSWORD` 必须使用网易邮箱开启 SMTP 后生成的“客户端授权密码”，不是网页登录密码；不要把真实密码写入脚本、CSV 或 Git。

### 2. 先预览发送内容

以下命令不会发信，只校验收件人、主题、正文和附件路径：

```bash
python3 Private_NAV/smtp_163.py \
  --to harryji088@163.com \
  --subject "私募净值更新 2026-08-21" \
  --body "您好，附件为本周新增私募净值，请查收。" \
  --attachment Private_NAV/output/新增净值_YYYYMMDD_HHMMSS.xlsx \
  --dry-run
```

确认附件是**本次实际更新后**生成的文件、`待复核` 内容已处理或已说明后，再正式外发。

### 3. 正式发送

去掉 `--dry-run`：

```bash
python3 Private_NAV/smtp_163.py \
  --to harryji088@163.com \
  --subject "私募净值更新 2026-08-21" \
  --body "您好，附件为本周新增私募净值，请查收。" \
  --attachment Private_NAV/output/新增净值_YYYYMMDD_HHMMSS.xlsx
```

可选抄送：`--cc colleague@example.com`；可选密送：`--bcc audit@example.com`。外部邮件具有不可撤回性，收件人和附件必须在预览后再次确认。

## 九、常见问题

### 产品没有导入

先确认其正式名称已在 `私募名单.xlsx` 中；若来自 `更新.xlsx`，再确认 `COLUMN_MAP` 有正确的列名映射。未映射产品不会自动猜测导入。

### 同一天有两条不同净值

脚本会将其列入待复核，保留原库记录。需确认数据源、份额类别和日期后，再决定是否以新的经确认数据重新处理。

### 163 邮箱报认证失败

确认已在网易邮箱设置中开启 SMTP 服务，并使用客户端授权密码。常见错误是填入网页登录密码，或邮箱账号与 `MAIL_FROM` 不一致。

### 截图无法确定产品

不要写入 `accepted`。以 `review` 状态保留在批次和输出报告中，待拿到产品名、份额信息或更多历史净值后再匹配。

## 十、每周收尾清单

- [ ] 新产品已先加入 `私募名单.xlsx`，并补充必要别名映射。
- [ ] `更新.xlsx` 已预检并实际导入（如本周有该文件）。
- [ ] 截图已识别；不确定项均进入待复核，未误写入。
- [ ] 已打开并核对本次 `新增净值_*.xlsx`。
- [ ] 已保留自动备份，未手工覆盖净值库。
- [ ] 邮件已使用 `--dry-run` 核对收件人和附件。
- [ ] 正式邮件已发送，并保留本次输出文件作为发送记录。
